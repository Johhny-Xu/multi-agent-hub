**Product telemetry is off.** This version sends no product analytics: no events, no daily snapshot and no requests to
PostHog or any other analytics service. It loads no third-party analytics client.

## What it is

- `src/lib/analytics.ts` keeps its exports (`analyticsEnabled`, `setAnalyticsEnabled`, `initAnalytics`, `track`) so its
  callers keep their shape. Every one of them is a no-op.
- `analyticsEnabled()` always returns false. No stored preference and no answer from an older desktop main can turn it
  on.
- `initAnalytics()` resolves without loading `posthog-js`; `track()` reads no preference and sends nothing.
- The `track()` calls still in the app's source are kept for their call sites. They are not a list of events that are
  sent, because none are.

## Turning it off

There is nothing to turn off: no setting enables sending. Settings → General still shows the Usage analytics switch for
older releases, and changing it changes nothing in this version.

## Never sent

Nothing is sent, so nothing can be. These stay the rules for any release that sends analytics again:

- API keys, tokens or passwords, or anything derived from them: no length, prefix, hash or last characters.
- Names of bots, rooms, teams, people, routines, files, devices, models, presets or accounts.
- Emails.
- URLs, hosts and addresses.
- File paths, and ids of any kind: bot, room, conversation, instance, account or computer.
- Instructions, prompts, message content, model output and error messages.
