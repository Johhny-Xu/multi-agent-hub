### 2.3 Trae：假「已签到」→ 真能签，中间踩了 4 层

| 层 | 问题 | 修法 |
|---|---|---|
| 1 | localStorage 里存在 `trae-cn-credits-billing-status` 就判「今日已签到」 | 改为先 `POST /trae/api/v2/ug/checkin_credits/status` 再决定是否 `claim` |
| 2 | 认证头写成 `Bearer`，真实是 `Authorization: Cloud-IDE-JWT <jwt>` | 已改；body 只有 `{req_source:1}`，多带字段会 `9004 order parameters are incorrect` |
| 3 | `1001` 被当成「JWT 过期」，提示「去客户端重新登录」 | `1001` 实际是**服务端注销了这个会话**（单端登录顶号 / 别处重登），提示改成可点的「重新登录」并用控制台自带 OAuth |
| 4 | `x-device-id` 每次 `randomUUID()`，等于每次伪装一台新设备 → 必然 `9074` | 见下（决定性修复） |

**9074 的真相**：文案是「当前参与用户太多」，实际最常见的成因是 **`x-device-id` 不是客户端注册过的那个 id**。服务端按设备认，没注册过一律 9074。

**最终方案**（`console/checkin.mjs`）：
1. `resolveTraeDeviceId()` 从 Trae 客户端日志里捞注册结果：
   `~/.config/Trae CN/logs/*/main*.log`（备选 `~/.trae-cn/logs`）里的
   `[ICDRS] (constructor) did: <id>`，倒序扫最新 20 个目录，命中后缓存到
   `~/.config/agenthub-codearts/trae-device-id`。
2. 允许 `TRAE_DEVICE_ID` 环境变量覆盖（没装客户端的机器用）。
3. 拿不到才回落到 `sha256(uid:hostname)` 派生的兜底 UUID（大概率仍 9074，只作占位）。
4. 请求头与客户端 `_applyUgDeviceHeaders` 对齐：`x-device-id` + `x-device-brand` / `x-device-type` / `x-os-version` / `x-app-version`。

**另修**：9074 退避重试 3 次（3s / 6s）；状态里加 `retryCount`，定时器只补「今天没签」和「今天签失败且重试 <6 次」的平台，不再因为一个平台失败就把全部平台重打一遍。

### 2.4 Trae 登录：浏览器 OAuth 已被官方关掉

- `AuthCode` 兑换失败时旧代码用「最后一个域名的错误」当结论，三个 origin 里两个 404，于是永远显示 `HTTP 404`，把国内端点的真实原因盖掉。现在按 host 收集全部错误，优先展示非 404 的那条。
- **20405 `Device proof required`**：Trae 给授权码兑换加了设备证明（客户端私钥/证书），浏览器 OAuth 这条路已经走不通。现在单独提示「请在 Trae 客户端登录，或用配置 Token 粘贴 JWT」，不再让人对着 401 反复重试。

### 10.2 凭据复用（本次核心）
旧实现的三个问题：

| 问题 | 后果 |
|---|---|
| `listCheckinAccounts` 里 `same.token = same.token \|\| live.token` | **档案里的旧快照压过 CLI 当前凭据**，签到用过期 token |
| 每个来源「第一个能读的就 return」 | 共享会话 / `.codebuddy` 可能比 `.codebuddy-cn` 新，却读不到 |
| 手工配置 Token 优先于 CLI | 手工 token 失效后签到天天失败，而 CLI 里明明是好的 |

现在的做法：
- `readCredCandidates()` 把一个目录下**所有**凭据读出来（含 `refreshToken` / `file` / `mtime` / `domain`）。
- `readCredFrom()` 按 **JWT exp → 文件 mtime → 来源优先级** 择优。
- `listCheckinAccounts()` 按 identity 合并，同一账号只留最优的一份；不同 UID 各自保留。
- `checkinWorkBuddy()` 签到前 `ensureFreshWorkBuddy()`：距过期 <2h 或 401 时，用 refreshToken 走
  `POST /v2/plugin/auth/token/refresh`（与 CLI 同端点、同 header）续期，**写回 CLI 的 `auth.info`**。
- 自定义 Token 解析出真实 identity 后，只在 CLI 没有该账号时才追加（`mergeCustomAccount`）。
- WorkBuddy **只读国内站**：`.codebuddy-cn/auth.info` + 共享会话；国际版 `.codebuddy/auth.info` 不参与。
  （实测踩到：国际版 token 有效期到 2027，按 exp 择优会赢，但签到端点 `www.codebuddy.cn` 不认它。）

界面：凭据行显示「CLI 实时凭据 · 自动续期」，账号行 hover 显示各自来源。

## 八、今日踩坑与机制备忘

1. **Trae 的 9074 不是限流**：文案「当前参与用户太多」会把排查带偏，真实主因是设备号没注册。改动前每次 `randomUUID()` 必失败，不是概率问题。
2. **Trae 浏览器 OAuth 已死**：`20405 Device proof required` 是官方新增的设备证明，不是网络问题、不是域名问题，重试无用。控制台侧只能「配置 Token」。
3. **`1001` 不是过期**：JWT 的 `exp` 往往还没到，是服务端注销会话。判断要看 `code`，不要看时间。
4. **多域名兑换要收集全部错误**：`lastErr` 每轮覆盖，最后一个 404 会把真实业务错误盖掉——这类「逐个尝试」的循环一律收集数组再挑。

6. **签到状态文件在 `~/.agenthub/checkin-state.json`**（不是 `~/.config/agenthub-codearts/`），设备号缓存才在后者。
