## 1. 项目背景与交付目标

**Multi-Agent Hub** 是面向多平台自主编码代理（Coding Agents）的集中化调度枢纽与全景控制台。项目打通了包括 Google Antigravity、GitHub Copilot、Huawei CodeArts、Xiaomi MiMo、MiniMax Code、Tencent CodeBuddy（国际版 / 企业版）、ByteDance TraeCode 以及智谱 ZCode 在内的 9 大主流 AI 编码环境。

本次交接围绕用户提出的核心技术诉求全面完成：
1. **全接口高强度压力测试与并发加固**：针对高频调用接口进行阶梯式并发压测，优化并发锁与连接队列，杜绝丢单与高尾延迟。
2. **大任务负载与管道流转**：保障 100KB+ 上下文提示词及长耗时异步任务的稳定落盘与状态流转。
3. **WebUI 视觉重构与现代化交互**：彻底消除原有简陋的双红框与原生 `<select>` 控件，推出 **Dark-Glass Model Studio** 与统一卡片设计。
4. **全 Worker 100% WebUI OAuth 登录免终端闭环**：无需 SSH 登录服务器执行命令行，全部在浏览器网页内完成官方授权与回调写入。
5. **多账号隔离体系与自动发现**：彻底解决“添加账号后跟没添加一样”的缺陷，实现沙箱隔离授权、账号身份自动嗅探（Email、UID、AK 等）、卡片头标与交互式账号胶囊 Chips 即时呈现及单键热切换。
6. **网络层底层修复**：重构 Node 原生 TLS Socket Chunked 解析器，解决 Google Antigravity 配额抓取截断，实现 Token 自动刷新。

## 3. 本次重大技术攻坚与核心缺陷修复

### 3.1 彻底解决“添加账号后跟没添加一样”与“误判登录成功”
- **原问题根因**：
  1. 过去直接在宿主机 `$HOME` 下执行登录，如果 `$HOME` 下已经存在某个旧账号凭据，用户点击“我已完成授权”时，系统检测到 `$HOME` 文件存在，误判为新账号已成功生成并退出了沙箱，导致旧凭据未变、新凭据根本未写入。
  2. 即使账号存入了数据库，前端卡片只将账号堆叠在隐藏很深的下拉框内，界面上看不到当前生效账号，缺乏直观视觉反馈。
  3. 用户浏览器长期打开同一个标签页，浏览器内存中缓存了旧版 JavaScript。
- **重构方案**：
  1. **全链路沙箱隔离 (`effectiveSandbox`)**：所有 OAuth 登录均指定专属临时目录（如 `/tmp/ah-auth-sandbox-...`），执行登录后必须严格在沙箱中产生新文件；未产生新凭据时禁止触发入库，并给出友好提示。
  2. **账号身份自动感知与格式化**：
     - Antigravity：自动解码 JWT 或读取 OAuth 配置提取 Google Email；
     - Copilot：提取 GitHub 登录用户名；
     - Xiaomi MiMo：提取小米账号 UID；
     - TraeCode：解析 JWT 获取 Trae 用户 UID；
     - CodeArts：解析脱敏 Access Key（AK）；
     - CodeBuddy：提取注册邮箱与手机号。
  3. **交互式账号胶囊 Chips (`.uh-acc-chip`)**：
     - 卡片顶部标头即时显示 `👤 <display/email>` 徽章。
     - “账号与登录”栏目渲染可视化胶囊列表：激活账号带绿色微光和“当前”徽章；备用账号单机即切（热切换无需重启服务）；每个胶囊右侧带 `×` 键可直接删除。
  4. **版本指纹与前端 SSE 热重载**：
     - 服务端每次启动计算 `BUILD_ID = ${VERSION}-${Date.now()}` 并随 `/api/events` 首次下发。
     - 前端比对 `buildId`，检测到服务重启或升级时自动 `location.reload()`，保证前台逻辑绝对最新。

### 3.2 解决 Google Antigravity 配额抓取崩溃 (TLS Chunked Parser 重构)
- **原问题根因**：
  Google `fetchAvailableModels` 接口返回 12KB+ 的 JSON 数据，且通过代理以 HTTP/1.1 `Transfer-Encoding: chunked` 形式返回。先前的旧代码使用自定义字符串切片函数 `decodeChunked(text)`，直接在 UTF-8 字符边界上切分十六进制字节长度，导致多字节字符截断，JSON 解析抛出语法错误，配额显示为“不可达 / 空”。
- **重构方案**：
  废弃旧有脆弱的手工切片逻辑，改用 Node.js 原生 `https.request`，将 TLS 代理套接字作为流式通道传入（`createConnection: () => tlsSocket`），利用 Node 底层 C++ 原生 `llhttp` 解析器完整还原分块流。现在全部 27 个 Google 内部及公开模型及 5 大核心配额条目 100% 稳定解析展示。

### 3.3 Google OAuth Token 自动续期
在 `TOKEN_READERS.antigravity` 中增加了 `token.expiry` 预检机制。当检测到 Access Token 距离过期不足 5 分钟时，自动携带 `refresh_token` 并通过本地代理向 `https://oauth2.googleapis.com/token` 请求刷新，将最新 Token 热写回文件，保障长期后台任务不掉线。

### 3.4 废除简陋双红框与原生 Select，推出 Dark-Glass Model Studio
- 将卡片原本割裂的模型配置与状态行合并，精简视觉噪音。
- 引入全屏暗色毛玻璃弹窗（Dark-Glass Popover），支持按厂商分类标签（Google / Anthropic / Huawei / GLM / Xiaomi）、模型能力徽章（Thinking 深度思考 / Vision 视觉 / 1M 超长上下文 / Fast 极速响应）进行一键过滤、实时试用与一键设为全局默认。

## 7. 常见故障排查指南 (Troubleshooting)

### Q1: 某 Worker 提示“未登录”或“凭据已过期”怎么处理？
- **排查与解决**：直接在 WebUI 控制台对应卡片中点击 **「🔐 OAuth 登录」** 按钮。系统会弹出模态窗，展示官方授权链接或设备码。在本地浏览器完成授权后，回到界面点击“我已完成授权”或粘贴回调链接，凭据将自动刷新并自动添加为当前生效账号。

### Q2: 想要添加同平台的第二个账号（多账号多租户）？
- **操作方式**：在对应卡片中点击 **「+添加新账号」** 按钮，系统会启动隔离沙盒进行登录。授权完成后，新账号会自动加入卡片的账号列表，并以交互式胶囊 Chips 展示，点击任意胶囊即可秒级热切换生效。

### Q3: Google Antigravity 配额抓取超时或提示 403 / 401？
- **排查重点**：
  1. 检查 `n5095` 上的本地网络代理是否正常（控制台 `fetchViaProxy` 默认使用 `http://127.0.0.1:7890`）。
  2. 若返回 401，说明 Google OAuth Refresh Token 失效，只需在 WebUI 重新点击一次 OAuth 授权即可。

### Q4: 端口占用或服务未启动？
- `8890`：控制台主 HTTP 端口
- `8765`：Hub Python MCP 端口
- 若端口被异常残留进程占用，可通过 `ss -tlnp | grep 8890` 查看 PID 并通过 `kill -9 <PID>` 清理后执行 `systemctl --user restart agent-hub-console.service`。

## 8. 后续演进建议与展望 (Roadmap)

1. **多账号配额智能轮询（Auto-Failover Pool）**：
   当前系统已实现多账号沙箱存储与一键热切换。后续可引入账号池轮询机制（Round-Robin Pool），当检测到主力账号配额消耗达到 95% 或命中 429 速率限制时，后台自动无感切换至备用账号继续执行任务。
2. **任务失败自动重试机制与 Worker 健康熔断**：
   当某 Worker 在连续 3 次大任务中超时或进程异常退出时，Hub 自动将其标为 `standby` 降级，并将待派发任务无缝转移至具备等价代码能力的备用 Worker（如 ZCode 降级至 CodeBuddy 或 Antigravity）。
3. **多租户权限细化与凭据加密存储升级**：
   目前除 ZCode 采用 `enc:v1:` AES-256-GCM 加密外，部分凭据存储为本地配置文件。未来可全量对接主密钥统一派生与 Linux Secret Service / Keyring，提供更严苛的企业级数据防护。
