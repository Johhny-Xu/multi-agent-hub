## 三、必须记住的技术机制与坑

### 1. 这个仓库的行尾，别再踩

`core.autocrlf=true` → **工作区 .py/.md 是 CRLF，但 git 索引统一 LF**。

→ **对 LF 内容做的补丁，必须用 `git apply --cached`，普通 `git apply` 会失败。**
→ 比对两棵树时若不归一化行尾，会得到大量「三方不同」的假阳性。**先 `replace(b'\r\n', b'\n')` 再比。**
→ `--cached` 能正确记录 mode 变更（`100644 → 100755`）；`git archive` 会带上执行位。

### 2. Windows 回归套件在本机极不稳定（已定量）

**同一份代码**在不同负载下的实测结果：

| 树 | Windows 结果 |
|---|---|
| v0.9.9.8（版本对齐后） | **30/32** |
| v0.9.9.7（版本对齐前，同代码） | **27/32** |

三个反复出现的失败**全是墙钟超时/阈值，单独跑都通过**：

| 套件 | 单独跑 | 套件上限 |
|---|---|---|
| `packaging` | 26/26，需 **235s** | 180s |
| `windows_launcher` | 5/5（71.7s / 78.7s） | 90s |
| `windows_bus` | `probe_elapsed` 1.76–2.20s | 1.5s 阈值 |

→ **判定回归必须做 A/B（`git archive HEAD` 到临时目录对比跑），不能只看单次结果。**
→ **跑计时类测试务必串行。** 我曾把 `windows_bus` 与后台 `packaging_smoke` 并发，导致 3/3 稳定失败，串行后结论完全不同。

### 3. 私有仓库的 Release 附件验证方式

匿名下载 Release 附件会 **404**（private 仓库的预期行为，`v0.9.9.6` 同样如此）。正确的可下载性验证是走 **API asset URL + `Accept: application/octet-stream` + Bearer token**：

```
GET https://api.github.com/repos/<owner>/<repo>/releases/<id>/assets/<asset_id>
    -H "Authorization: Bearer $TOK"
    -H "Accept: application/octet-stream"
```

用 `browser_download_url` 直接 curl 会 404，别被误导。

### 4. 凭据在 Linux 上，不在 Windows

GitHub token 在 `n5095:~/.config/github-copilot/copilot-token`（`gho_` 前缀，40 字符，权限 600）。**Windows 本机没有。** 发布 Release 需在 Linux 上操作。

### 5. `SHA256SUMS` 的行尾陷阱

`build.py` 生成的 `SHA256SUMS` 是 **CRLF**，在 Linux 上 `sha256sum -c` 会报 `No such file or directory`。且它**只覆盖 4 个 ZIP**，不含扩展三件套。

上版（v0.9.9.6）的约定是：**LF 行尾 + 覆盖全部 7 个产物 + `*` 二进制标记**。本版已按此重做（见 `gen_sums.py`）。

### 6. `docs/` 无法「只删证据、留文档」

`release-0.x.md`、`*-compatibility.md` 这些**本身就是证据索引**，保留它们就必须保留它们索引的全部 JSON。且它们大量使用**相对路径链接**（`](release-0.7-lan.json)`）而非 `docs/` 前缀——只匹配前缀的分析会漏掉这些，造成 71 处死链。

### 创建 Release 并上传附件（凭据在 Linux）
```bash
# 1) 把 $OUT 整个传到 Linux
scp -r $OUT/* n5095:/tmp/relXXX/

# 2) 在 Linux 上创建 Release
TOK=$(cat ~/.config/github-copilot/copilot-token | tr -d '\r\n')
# body 用 RELEASE_NOTES.md，注意 generate_release_notes 设 False

# 3) 上传附件（uploads.github.com，注意 name= 查询参数）
for f in agenthub-*.zip multi-agent-hub-*.{vsix,carts,cloudide} SHA256SUMS RELEASE_NOTES.md; do
  curl -X POST -H "Authorization: Bearer $TOK" -H "Accept: application/vnd.github+json" \
    -H "Content-Type: application/octet-stream" --data-binary @"$f" \
    "https://uploads.github.com/repos/Johhny-Xu/multi-agent-hub/releases/$RID/assets?name=$f"
done
```
