## 二、四件事的根因与实现位置（别再重复劳动）

### E. 华为模型重复：同一 id 挂了 5 个别名

**现象**：控制台模型列表里 `GLM-5.3 / [默认] GLM-5.3 / glm5.3 / gm5.3 / glm-5.3 / huaweicloud-maas/gl…` 六行。

**根因**：`agents.json` 里同一个模型 id 存了 5 个别名，而 `listModels()` 的「自定义模型追加」是**逐别名 push**，
一个 id 刷出一行，于是 5 个别名 = 5 行重复。

**修复**（`console/auth.mjs`）：
- `listModels()` 自定义段落改为**按 id 归并**（`Map<id, aliasList>`），并给每组挑一个显示名 `pickDisplayAlias()`
  （评分：与 id 末段同形 +4 / 含大写 +2 / 等于全 id −1 / 超长 −3）；
- `CATALOG_MODELS.codearts` 首位补 `{ id:'huaweicloud-maas/glm-5.3', name:'GLM-5.3', default:true }`，并补 `GLM-5.2`；
- `console/server.mjs` 的 `MODEL_CATALOG.codearts` 同步为 5 条；
- 归并后的模型带上 `aliases` / `removableAliases`，删别名时不会误删整个模型。

**线上实测**：`/api/models` → `codearts count=5`，`GLM-5.3 | huaweicloud-maas/glm-5.3 | default=True` **只出现一次**。

### F. 文件编辑权限：每家 CLI 的开关不一样，不能照搬

**架构决策**：**不在前端硬编码**。开关定义放在能力表里，由 Python 枢纽解析成命令行参数。

链路：

```
hub/capabilities.json  permission.modes
        │  （每个 worker 自己一段，args 就是该 CLI 的真实开关）
        ▼
hub/task_contract.py    prepare_task()  → extra_args
        │              public_model_capabilities() → 下发给控制台
        ▼
console/server.mjs     normalizeCapabilities() / taskCapability() 校验
        │              chatSend() / dispatchAsync() / POST /api/chat/send 透传
        ▼
console/client/index.html   #mp-row-permission 按 allowed 渲染按钮
```

各家的映射（**已逐条实测**）：

| worker | allowed | 实际参数 |
|---|---|---|
| codebuddy / codebuddy-cn | default / readonly / edit / full | `--permission-mode plan\|acceptEdits\|bypassPermissions` |
| antigravity | default / readonly / edit / full | `--mode plan\|accept-edits\|auto` |
| opencode | default / readonly / full（**无受控**） | `--agent plan` / `--auto` |
| cline | default / readonly / full（**无受控**） | `--plan` / `--yolo` |
| github-copilot | default / full（**只有全放行**） | `--allow-all-tools --allow-all-paths` |
| codearts / minimaxcode | 仅 default | 无开关，UI 显示「该子代理未提供开关」并置灰 |

`codearts` 传 `readonly` 时 `prepare_task()` 会**明确报错并列出可选值**，不会静默忽略。

UI 细节：`#mp-row-permission` 与「思考程度」并排（`.mp-params-container` 由 column 改 `row + wrap`），
标签右侧的小字直接显示该 worker 的开关名（`--plan / --yolo` 这种），用户一看就知道加了什么参数。
`getModelSummaryText()` 会在按钮下方汇总当前选择，发送 payload 带 `permission` 字段（`default` 不发送）。

### G. opencode 账号名 `si***ow (2 ***供方)`

两个独立原因叠在一起：

1. **打码过头**：`maskPart()` 无条件把中间字符打成 `***`，把展示名也打了。修复：新增 `looksLikeIdentifier()`，
   只有「像标识符」的串才打码（含 `@`、`UID:`/`AK:` 前缀、或 ≥12 位纯 ASCII 无空格），
   含中文或带空格的原样显示。
2. **显示名被固化**：`display` 在建档时写进 `meta.json`，旧代码固定拼 `「(N 个提供方)」`，
   单提供方也带后缀，于是升级后列表仍是 `opencode (1 个提供方)`。
   修复：新增 `formatProvidersDisplay()`，**列表侧按 identity 现算**，不再信任冻结字符串。

现在 provider 集合的显示规则：1 个provider 就写它自己；2~3 个并列（`opencode + siliconflow`）；更多写 `opencode 等 N 个提供方`。

**线上实测**：`opencode` 一条 + `历史 2`（两个旧 provider 组合已收起）。

### H. minimaxcode 名称不显示 + 一个号两个名字

**根因**：
- `~/.mmx/config.json` **只有 `region` + OAuth token，没有任何账号标识**，所以 `identity` 只能退化成**整份文件的指纹**；
- token 一刷新（`expires_at` 变）指纹就变，`_autoSyncLiveAccount()` 认不出是同一个号 → **每次刷新裂一个新档案**；
- `display` 回退成目录名 `mmx-cn-5cc0eb`，前端一脱敏就成了 `mm***eb`，等于没名字。

**修复**（`console/accounts.mjs`）：
- `identity` 改成 **`mmx:<region>`**（单槽位语义：mmx 一个 region 只有一份 config.json，天然唯一），跨 token 刷新稳定；
- `display` 回退成 **`MiniMax · 中国区`**（不再拿指纹/目录名当名字）；
- `_autoSyncLiveAccount()` 新增 **规则 2d**：身份从指纹升级成 `mmx:` 后旧档案必然匹配不上，
  按「同 worker 取 `savedAt` 最新的一份原地复用」兜底，**迁移时不额外裂档**；
- 步骤 1（凭据逐字节一致）现在会**按真值刷新** `meta.identity` / `meta.display`，不再只在字段缺失时补齐
  （旧版本会把脏值永久留下）。

**线上实测**：`MiniMax · 中国区`（identity `mmx:cn`）一条 + `历史 1`。

### 顺带修掉的通用问题：历史快照被当成「另一个账号」

新增两个导出函数（`console/accounts.mjs`）：

- `isMutableIdentity(identity)`：判断身份方案是否「可变异」——`providers:` / `mmx:` / 纯 12 位指纹。
  这类身份描述的是**这份凭据文件**，不是独立账号；而邮箱 / UID / AK 是稳定身份，不一致代表真的是另一个账号，**必须保留**。
- 列表为每个档案加 `stale` 标记（可变异身份 + 与线上当前身份不一致 + 不是 active），并汇总 `staleCount`。

前端（`console/client/index.html`）把 `stale` 的档案收进一个 `历史 N` 胶囊，点开才展开（仍可切换 / 删除），
默认只显示当前账号——这就是「我只登录了一个号却看到两个」的正面解法，**不删任何文件**。

```

```

`identity` 的种类直接决定去重行为：

| 种类 | 例子 | 一致性含义 |
|---|---|---|

| 单槽位 | `mmx:cn` | **可变异**：一个 region 只有一份配置 |

> 新增 worker 时**优先找稳定身份**（JWT claim / uid / AK）；实在没有才用指纹，

## 七、本会话踩过的坑（务必避免）

1. **PowerShell / Git Bash 会改写引号**：`ssh n5095 "python3 -c '...'"` 里的括号会变成 `syntax error near unexpected token '('`，
   甚至把 `:` 改写成 `:/`。**统一用 `ssh n5095 'bash -s' <<'REMOTE' ... REMOTE` 或先落文件再执行**。
2. **`safe-delete` 会 fail-closed**：删带锁文件的目录时报 `SAFE_DELETE_FAIL_CLOSED`，
   先停占用进程（`taskkill /PID <pid> /T /F`），再删；`nul` 这类设备名要先 `mv` 改名再删。
3. **`padding` 简写会覆盖 `padding-bottom`**：移动端给列表让位的那条 `padding-bottom` 被 `padding: … !important` 吃掉，
   内容会被底部导航压住。**必须用 longhand**。
4. **`position: fixed` 的元素不在文档流**：想把胶囊排到返回按钮右侧，只能 JS 实测按钮的 `right` 再写 `left`。
5. **UA 判移动端不能只看 `maxTouchPoints`**：无头环境下 `maxTouchPoints=10`、`screen` 恒为 800×600，
   会把 1440×900 桌面判成移动端。触屏兜底必须 **`(pointer: coarse)` 且 `(hover: none)`**。
6. **API Key 登录不要做格式门禁**：多行粘贴、前缀拼错、裸 Key 都会误判。
   现在一律只拦「空输入」和「回调链接」，猜不中就落默认 provider 并提示。
7. **改 `meta.json` 的显示名要谨慎**：它是**冻结字符串**，`display` 一旦写死就会被永久沿用；
   凡是从「可变身份」推导出来的显示文案，都应该在读取时**现算**，而不是信任 meta。
