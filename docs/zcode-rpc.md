`drivers/zcode_rpc.mjs` runs the installed official ZCode `app-server` through its NDJSON protocol. It creates its own temporary `ZCODE_STORAGE_DIR` and workspace key, opens deferred sessions, discovers the official model catalog, and requires an explicit model before sending a task. The catalog match must be unique. A missing model returns `blocked_model` without `session/send`; it never substitutes another model.

Use `node drivers/zcode_rpc.mjs --cli <absolute-zcode.cjs> --model <model-id-or-provider/model> --task <task> --cwd <workspace> --timeout 300 --stream on`. The existing official provider configuration can be referenced through `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE`; the adapter does not read or copy its credentials. Repeat `--attach <absolute-local-path>` for up to eight files. Recognized image extensions are mapped to `{type:"image",path}`, other regular files to `{type:"file",path}`. The Hub must resolve transported attachments to files on the worker machine before invoking this driver.

ZCode 0.16.9 catalog refs can omit reasoning options while `settings.model.current` includes them. For the same requested current model, the adapter preserves those official options. The implementation of `session/create` formats its model ref as a string and drops `options`, so the same create request also supplies the retained `thoughtLevel`. Before sending, both `session.model` identity and `settings.model.current` options must match. The adapter does not call model or thought-level setters, and does not change a user's global or existing workspace model. `thinking=on/off` is explicitly rejected: this adapter has no verified boolean thinking contract. `default` preserves the verified current setting when available; a different model requiring unavailable selection options fails before generation.

The adapter requests `plan` mode, disables MCP for the worker session, and explicitly denies Write, Edit, Bash, WebFetch, WebSearch, Task, and Agent. Actual installed 0.16.9 snapshots reported `build` despite the plan request; write/edit denial therefore does not depend on the mode label. Validation covers question answering; file writing is not supported. Attachments are passed through the official session input API. A task is sent once. Transport uncertainty returns `unknown`; permission requests are denied rather than automatically approved. Idle snapshots, cancellation, execution errors, empty responses, and timeouts do not count as success.

Streaming publishes only a known text part whose assistant role has been confirmed by an official `session/read` snapshot. Reasoning, tool input/output, user text, and unknown part types or roles stay hidden. Final success requires `turn.completed` with `resultType=success` and nonempty response. The real Windows smoke requested streaming but emitted no confirmed body increments, so realtime delivery remains unverified; the final body was correct.

On 2026-10-08, the installed Windows ZCode 0.16.9 catalog contained 13 entries and lacked `GLM-5.3-Flash`. Its preflight returned `blocked_model` with zero sends. One separate, explicitly selected `wx/Deepseek-v4-flash` task sent once and returned exactly `HUB_ZCODE_RPC_SMOKE 122`. This proves the adapter's available-model execution, not the declared GLM default. All created sessions, owned servers, and temporary runtime storage were cleaned up. See [sanitized real evidence](zcode-rpc-preflight.json), [actual public metadata fixtures](../tests/fixtures/zcode_rpc_metadata.json), and [22 offline regressions](../tests/zcode_rpc.test.mjs). The protocol shapes were checked against the installed official public bundle; the [official CLI repository](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/README.md) describes the host entry point.

After that live smoke, the only driver change added Write/Edit to the denylist, with an updated offline assertion. The evidence retains the live-tested hash and separately records the stricter final version; no additional model task was sent for that restriction.
