## 一、长任务超时：为什么 600s 会切断正在干活的 CLI

### 1.1 现象

十几个分钟的 CLI 任务跑到一半被回收：

```
⚠️ 任务未完成（timeout）：[qoder-4911ba431b] agent=qoder status=timeout
CLI 任务超时 (>600.0s), 已回收子进程树
```

Qoder 最先暴露，但这是 `hub/async_worker.py::run_cmd_mode` 的公共路径，**所有走异步 CLI 的 worker 都一样**。

### 1.2 根因

```python
deadline = time.monotonic() + timeout_s      # 起始 + 600s
while proc.poll() is None:
    remaining = deadline - time.monotonic()
    if remaining <= 0:
        raise CommandTimeout(...)             # 与「有没有在产出」完全无关
```

一条**总时长**判定，与任务是否仍在产出无关。各层默认值还互相打架：hub 600 / MCP dispatch 900 / console `/api/dispatch` 又夹到 600，长任务必撞。

### 1.3 修法（`hub/command_runtime.py` + `hub/async_worker.py`）

| 概念 | 含义 | 默认 | 环境变量 |
| --- | --- | --- | --- |
| `timeout_s` | **无进展预算**：连续这么久没有任何新字节写入才判卡死 | 900s | `AGENTHUB_CLI_IDLE_TIMEOUT_S` |
| `hard_timeout_s` | 绝对上限，只兜住「永远有输出、永远不结束」的刷屏死循环 | 6h | `AGENTHUB_CLI_HARD_TIMEOUT_S` |

四个配套细节：

- **进度信号换成字节增长**（stdout + stderr 的 `getsize`）。原来只看「解析后的文本是否变化」，CLI 把进度打在 stderr 或只吐结构化事件时会被误判卡死。
- **心跳**：无输出期间每 60s 刷新一次 `updated_at`。Hub 的 `HUB_STALE_RUNNING_SEC`（30 分钟无进展）本来是用来收「worker 已死」的记录；模型思考时常常十几分钟不出字，没有心跳就会被误杀。
- **超时不再丢成果**：`status=timeout` 时把最后 ≤20000 字符写进 `partial_text`，`hub_result` / `hub_result_json` 都会带出，可据此续跑；`timeout_kind` 记录是 `idle` 还是 `hard`。
- **`hub_dispatch_cli` 新增 `hard_timeout_s`**；MCP 与 console 的文案、上限对齐（`/api/dispatch` 上限 600 → 21600）。

### 1.4 验证

`tests/runtime_regressions.py` 新增 4 例：持续输出不被切、静默按 idle 超时且保留 `partial_text`、硬上限生效、timeout 落盘字段。
端到端：`timeout_s=1` 下持续输出 4.8s 的任务返回 `completed`；静默任务 2s 判 `timeout`（`partial_text` 保住输出）。

### 1.5 注意

- 「无进展预算」不是无限等：真卡死的进程仍会在预算内被回收，别为了「不切断」把 `timeout_s` 调到很大。
- 排队型服务（如 CodeArts 高峰期「模型排队」）在这段时间里没有任何输出，会被 idle 判定收掉。遇到就换模型或临时调大预算，**不要**把 `timeout_s` 调到几小时。
- 改动只影响 `async_worker.run_cmd_mode`；`trae_delegate` / `zcode_delegate` 仍是各自的绝对预算（900s / 1000s）。

## 二、看板娘：切到设置页还挂在页面上

### 2.1 根因

`#mascot-air` 是 `position: fixed; z-index: 80` 的**独立图层**。`#panel-chat` 被 `hidden` 之后它不会跟着消失：

- 下坠由 `requestAnimationFrame` 逐帧写坐标，擦汗靠 `setTimeout`，两者都不看面板状态；
- 原来的 `mascotOnScreen()` 只在「触发掉落」前判了一次。

### 2.2 修法（`console/client/index.html`）

- 新增 `abortAir()` 作为唯一收尾入口：取消 rAF、清擦汗定时器、关掉空中层所有视频、退出 `holding` 态、复位 `phase`。
- **坠落每帧**复查 `mascotOnScreen()`，面板一 `hidden` 立刻 `abort`。
- **hold / wipe 阶段**没有 rAF 兜底，用 `MutationObserver` 监听 `#panel-chat` 的 `hidden` / `class`。
- `HubMascot.hide()` 也走同一收尾。

### 2.3 验证

`tests/console_layout_theme_dom.mjs` 新增回归（vm 里跑 `abortAir`，断言 rAF/定时器被取消、视频关闭、状态复位）。
真机验证用**无头 Edge + 合成夹具**（`tests/console_browser_fixture.mjs`）跑 CDP：

```
下坠中  → air.is-on=true，可见空中层视频 1 个
点设置后 → air.is-on=false，可见空中层视频 0 个
```

### 3.2 三处不兼容（每处都踩到了）

| 变化 | 现象 | 处理 |
| --- | --- | --- |
| 启动脚本改用 `BASH_SOURCE` 定位自身目录 | 经 `~/.local/bin/codearts` 软链调用报 `~/.local/bin/bin/codearts: No such file` —— **升级后 worker 全挂** | 软链换成 3 行 `exec /home/johhny/.codeartsdoer/installers/codearts "$@"`；PATH 里的名字不变，下次升级也不会再坏 |
| 新增「文件夹信任」门 | `cwd` 不在 `trustedFolders` 时直接 `文件夹未被信任: <dir>`，驱动归类 `CODEARTS_PERMISSION_REQUIRED` | `~/.codeartsdoer/cli-data/settings.json` 里 `security.folderTrust.enabled=false`，并把 `/`、`/home/johhny` 留进 `trustedFolders`（备份 `settings.json.bak-20261023-*`） |
| `--format json` 输出混入提示 | 事件流本身没变（`step_start` / `text` / `step_finish`），但「模型排队」等 UI 提示会混在 stdout | 驱动原本就把非 JSON 行当诊断忽略，**无需改代码**；`codearts models` 表格格式也没变，目录解析照常通过 |

> 第 2 条是安全取舍：等于不再拦「未信任目录」。想收紧就改回 `enabled=true` 并只列实际使用的目录，代价是别的目录会直接失败。

## 六、还剩什么

1. **trae / zcode 通道仍是绝对预算**（900s / 1000s），长任务照样会被切；本轮只改了 CLI 通道。
2. **CodeArts 排队**：V4.1-Flash 高峰排到 250+ 位，排队期间无输出会被 idle 判定收掉；要么换模型，要么临时调大 `timeout_s`。
3. **`folderTrust.enabled=false`** 是本轮主动放宽的安全边界，需要收紧就改回 `true` 并显式列目录。
4. **AGENTS_JSON 不在仓库里**：线上真实配置在 `~/.config/agenthub-codearts/agents.json`，仓库只有 `hub/agents.example.json` 占位；
   新增 worker/模型时两边都要改，别只改仓库。
5. `~/multi-agent-hub`（服务器）与 `Desktop/codex/codearts/multi-agent-hub`（本机）是两份副本，发版以服务器那份构建，但改动要记得同步两边。
