## 七、新增：主代理可查子代理存活状态（`hub_task_status`）

### 7.1 为什么加

上一轮压测暴露出主代理只能看 `status=running`，CLI 静默计算时很容易被自己的墙钟截断。
这次把「进程/CPU/输出/心跳」变成 Hub 的一等状态，派发方不必靠猜。

### 7.2 实现

- `hub/process_liveness.py`：Linux 读 `/proc` 汇总整棵进程树 CPU（Windows 用 `OpenProcess` 回退 PID 存活）。
- `hub/async_worker.py`：
  - 运行记录增加 `pid` / `started_at` / `output_bytes` / `last_output_at` / `cpu_seconds` / `process_count` / `heartbeat`；
  - 每 10s 采样进程树 CPU，**CPU 增长也重置 idle 预算**（静默但真在计算的任务不再被 stdout 空闲误杀）；
  - GUI 进度轮询写入 `progress_at`，界面不变时也每分钟写心跳。
- `hub/agent_hub.py`：
  - 新增 `hub_task_status(ref, json=false)`；
  - `hub_result_json` 透传 `verdict` 与 `liveness`；
  - `hub_wait_result` 预算耗尽时打印存活结论；
  - `_reap_result` 遇到仍存活的 PID 不再按 `updated_at` 判 timeout；
  - 异步受理回执直接提示先查 `hub_task_status`。

### 7.3 verdict 语义

| verdict | 含义 | action |
| --- | --- | --- |
| `working` | 进程活 + CPU/输出有增长 | `wait` |
| `alive_waiting` | 进程活、心跳新，暂无输出（思考/排队） | `wait` |
| `alive_quiet` | 进程活但心跳偏旧 | `wait`（先查上游队列，别杀） |
| `gui_working` / `gui_waiting` | GUI 无 PID，按界面快照/心跳判断 | `wait` |
| `worker_exited_result_missing` | 进程退出但结果仍 running | `inspect_delivery` |
| `completed` / `error` / `timeout` | 终态 | `done` / `handle_error` / `inspect_timeout` |

首次查询建立 CPU/输出基线；10 秒后复查可看 `cpu_delta_seconds` / `output_delta_bytes`。
