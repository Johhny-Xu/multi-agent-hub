## 二、根因

`getCheckinOverview()` 里这一句：

```js
const accountRows = isToday && Array.isArray(pState.accounts) && pState.accounts.length
  ? pState.accounts                       // ← 今天签过就直接回放快照
  : (await listCheckinAccounts(plat))…    // ← 实时扫描只在「今天没签」时才用
```

于是「账号集合」被两份数据源各说一套：签到用它自己那天的快照，worker 用档案目录。
连带两个后果：

1. `runCheckin('due')` 与 30 分钟定时器只看**平台级** `status`，平台已 success 就不再进来，
   新账号当天永远签不到（按钮也被 `disabled` 锁死）。
2. `meoo` 压根没接档案扫描（`PLATFORM_WORKERS` 里没它、`readCredCandidates` 也没分支），
   `minimaxcode` 的身份写死成 `mcode:<region>`，多个账号会塌缩成同一行。

## 三、改动

### 3.1 `console/checkin.mjs`

- **`mergeAccountRows(live, snapshot, platform)`（新增）**：账号集合以实时派生为准，快照只补状态。
  - 实时有、快照没有 → `status: pending` + `fresh: true` + `message: 新增账号 · 今日待打卡`；
  - 快照有、实时没有 → 原样保留 + `stale: true`（凭据被删/切走，当天历史不能凭空消失）；
  - 配对键：`identity` → `name`；`minimaxcode` 额外把老快照的 `mcode-cn` 归一成 `mcode:cn`；
  - `meoo` 特例：老快照记的是用户名（`Johhny`）、档案名是 `meo-meoo_ak_`，两边各剩一行时配对，避免升级当天多一行假新增。
- **`getCheckinOverview`**：用上面的合并结果，新增 `pendingAccounts`（今天还没签成的账号数）与 `accountCount`。
  平台处在「等下一期开窗」（`retryAt` 未到）时 `pendingAccounts` 记 0——那会儿点也只会再拿一次 pending，
  白让按钮闪，用户还以为漏签。
- **`pendingAccountPlatforms(state)`（新增，已导出）**：返回「今天有新增账号」的平台，
  只认 `fresh`（从没尝试过）的，失败账号仍归平台级 `retryCount` 管，避免半小时一次重打失败号；
  同时尊重平台的 `retryAt`（Qoder 10:00 开窗）。
- **`runCheckin('due')` / `startAutoCheckinScheduler`**：把上面这批平台并进待签队列。
- **`PLATFORM_WORKERS.meoo = ['meoo']`**，`readCredCandidates` 新增 meoo 分支（`MEOO_AK=` 一行文本，identity = `meoo:<AK>`）。
- **`checkinMeoo`**：抽出 `checkinMeooOne(ak)`，改为遍历 `listCheckinAccounts('meoo')`；
  多账号轮完后用生效账号再 `login --ak` 一次，把本地 CLI 的「当前登录」写回去。
- **`checkinMiniMaxPlatform`**：遍历所有 mcode 档案；线上那份走原文件（保留 401 续期），
  档案快照把整份凭据（含 refreshToken）传给 `checkinMiniMax`。
- **`listCheckinAccounts`**：`minimaxcode` 的档案 identity 改成 `mcode:<region>:<档案名>`，
  并在合并后把「与线上同 token」的档案行合掉、沿用它更可读的名字。
- 各签到函数写快照时补 `identity`，下次能精确配对。
- `detectCredentials` 补 `meoo` 占位；删除从未被读取的 `PROFILE_CRED_FILE`。

### 3.2 `console/minimax-checkin.mjs`

`checkinMiniMax(region, override)` 的 `override` 现在同时接受「粘贴的 token 字符串」和「整份凭据对象」，
后者带 refreshToken，档案账号遇 401 也能自愈。

### 3.3 `console/client/qa-grid.js`

- 账号行名字后缀 `（新增）` / `（已切走）`；
- 渲染末尾统一同步所有 `.btn-do-checkin`（用 `data-platform`）：平台已签但 `pendingAccounts > 0` 时按钮保持可用，
  文案改成 `补签新增账号 N`（meoo 为 `补签 N 个账号`）。

### 3.4 测试

`tests/console_checkin_account_sync.mjs`（新增 8 例）：

1. 今日签完后新加的账号立刻出现（旧账号保留 success、新账号 pending+fresh、`pendingAccounts=1`）；
2. 新账号进补签队列；
3. 没有新增时 `pendingAccounts` 归零；
4. 老快照无 identity 按名字配对，不多出一行；
5. 凭据被移走的账号保留并标 `stale`；
6. Meoo 从档案派生并与线上同一 AK 去重；
7. MiniMax 两个档案不塌缩；
8. MiniMax 线上与同 token 档案合并成一行且沿用档案名。

## 五、遗留与注意

- **无签到接口的 worker 不会出现在签到区**：`antigravity / zcode / cline / opencode / mimocode / github-copilot`
  在 Hub 侧有账号档案，但没有可调的签到端点，故只在「子代理 · 账号」里出现。要覆盖得先有对应签到实现。
- **`stale` 行是当天的**：第二天快照被覆盖后自然消失，不做额外清理。
- **MiniMax 语义**：一个 region 只有一份线上凭据，档案多账号时只有 active 那份能自动续期；
  其余账号靠档案里的 refreshToken（`checkinMiniMax` 现在支持）。
- **meoo 的积分**：每日积分是网页登录时服务端发放，CLI 的 `login --ak` 不触发，所以只报余额不承诺涨幅。
- 既有问题（与本轮无关）：`tests/windows_bus` 的 zcode bridge fixture 偶发 `ECONNREFUSED`；
  `console_worker_parity` 在本机沙箱会触发 `reg.exe` 黑名单拦截（属沙箱策略，非用例缺陷）。
