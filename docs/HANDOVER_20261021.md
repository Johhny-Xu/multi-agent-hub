## 二、本轮修复

### 1. Qoder CN「明明没签到却显示已签到」

**现象**：卡片显示「今日已领取」，但 Qoder 客户端里「每天领 100 Credits」的按钮还是可点的。

**根因**：`checkin.mjs` 判定「今日已领」只看 `claimStatus === 'CLAIMED'`，**没有校验活动有效期**。上游返回的列表里带着上一期已领的老活动，于是直接走 `already` 分支，根本不去领今天的。

**修法**（对齐开源项目 `wallechfox/qoder-checkin`）：

```js
// CLAIMED 必须同时满足 startAt <= now < endAt 才算「今日已领」
function qoderInWindow(row, nowSec = Math.floor(Date.now() / 1000)) {
  const s = Number(row?.startAt ?? 0) || 0;
  const e = Number(row?.endAt ?? 0) || 0;
  if (!e) return true;              // 没有窗口字段就不限制，避免判死
  return s <= nowSec && nowSec < e;
}
```

同时把过期 CLAIMED 单独统计，并在消息里带诊断串 `[活动 N 个：CLAIMED/CLAIMABLE…]`，以后排查不用再猜。

**验证**：`POST /api/checkin/run {"platform":"qoder-cn"}` → 两个账号各「领取 1 个活动，+100 Credits」。

### 2. 签到日志点开是空白

**现象**：点「签到日志 (20)」标签，下面什么都没有，直接接下一个卡片。

**根因**：**HTML 少了一个 `</div>`** —— `#checkin-tab-history` 被嵌在 `#checkin-tab-grid` 里面。切到日志 tab 时 JS 给 grid 设 `hidden`，里面的 history 跟着一起被隐藏。DOM 里 `history.parentElement.id === 'checkin-tab-grid'` 就是这个症状的铁证。

**修法**：在 grid 的 `</div>` 后再补一个 `</div>`，让两个 tab content 成为兄弟节点；另加 `.settings-card-body > .checkin-tab-content { width: 100% }` 兜底。

**验证**：切到日志 tab，容器高度 454px、20 条记录正常显示。

### 3.4 Qoder 国际版为什么一直签不上（已解决）

**症状**：token 有效（没有 401，能拉到活动列表），但列表恒为 0 条 → 一直报「上游暂未下发每日积分活动」。

**根因**：上游**按设备**下发活动。我们代码里的 `Cosy-MachineToken/Code/Type` 是 `resolveRisk()` **合成**的，
不是真实 Qoder 客户端 `runtime-info.exe` 产出的那一套。指纹对不上 → 上游认为这台设备没有活动。

**解决步骤**（在有 Qoder 客户端的 Windows 上）：

```bash
# 1. 拉开源项目（git clone 可能被 TLS 拦，用 codeload zip）
curl -sL -o qc.zip https://codeload.github.com/wallechfox/qoder-checkin/zip/refs/heads/main
# 2. 预览（不写文件）
python 01_extract.py --no-write
# 3. 把输出里的 device 块三个值写进 ~/.config/agenthub-qoder/device.env
```

```ini
# ~/.config/agenthub-qoder/device.env（600 权限，不进仓库）
QODER_MACHINE_TOKEN=...
QODER_MACHINE_CODE=...
QODER_MACHINE_TYPE=...
```

**代码侧**：`qoder-device.mjs` 的 `loadQoderDeviceEnv()` 在 `resolveRisk()` 开头读取该文件（环境变量优先、文件兜底）。
**部署侧**：`agent-hub-console.service` 加一行 `EnvironmentFile=-%h/.config/agenthub-qoder/device.env`，重启生效。

**验证**：`POST /api/checkin/run {"platform":"qoder"}` → `Henry Baker` 领取 1 个活动 +100 Credits。

**注意**：指纹跟**机器**绑定，换机器/客户端重装后要重新提取；`花凄` 这个账号即使指纹正确也返回空列表，
大概率是该账号本身没有下发活动（不是代码问题）。

### 9.1 Qoder CN「没签却显示已签」的真正根因

不是设备指纹，是**窗口跨自然日**。上游活动按 UTC+8 每天 10:00 刷新，一期是 `[今天 10:00, 明天 09:59]`：

```
startAt=1792634400  → 2026-10-22T02:00:00Z = 10-22 10:00 +08
endAt  =1792720740  → 2026-10-23T01:59:00Z = 10-23 09:59 +08
```

0:00–10:00 之间，`CLAIMED` 的是**昨天那期**，只看「在窗口内」就会判成今日已领。现在 `qoderClaimedToday()` 要求窗口起始日是今天；
上一期已领 + 今天没开窗 → 返回 `pending` + `retryAt`（下一期 10:00），卡片显示「今日待打卡」，定时器到点补签（开窗前不空转）。
「刷新状态」按钮也从「只重读状态」改成 `POST /api/checkin/run {platform:"due"}`，会把今天没签成的平台补一刀。

**排查手法**（下次还遇到就这样抓）：`/tmp/qoder_probe.mjs` 的写法——`listCheckinAccounts(platform)` 拿账号 token，
再 `listQoderCampaigns(worker, token, device)` 打印每行的 `startAt/endAt/claimStatus`。窗口字段一定在原始行里。
